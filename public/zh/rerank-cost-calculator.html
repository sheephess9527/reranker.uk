重排序成本计算器

工具 · 更新于 2026 年 10 月 1 日

托管重排序服务的计费方式各不相同。Cohere 按检索次数计费 —— 一个 query 加最多 100 篇文档，超过 500 token 的文档会被算作多篇。Voyage 按 token 计费。两者实际差距比看上去小，哪家更便宜取决于你的段落长度怎么取整。填入你自己的数字试试。

为什么排名会变

两家最终都是按文本量收费，只是取整方式不同。Cohere 把每个候选按「每满 500 token 算一篇，不足也算」计费（query 计入在内），每次检索包含 100 篇文档。Voyage 只按你实际发送的 token 计费，query 按每篇文档各算一次。

按标价算，两家恰好在一个点上相等：500 token 的文本，在 Cohere Rerank 4 Pro（每次检索 100 篇，$0.0025）和 Voyage rerank-3（每百万 token $0.05）上花费完全相同 —— Voyage 自己的价格页用的就是这个例子。真正拉开差距的是取整：

  • 段落较短 —— Cohere 仍把每段按一整篇计费，所以按 token 计费更便宜，段落越短差得越多。
  • 刚超过 500 token 的边界 —— 520 token 的候选在 Cohere 算两篇；按 token 计费只要大约一半的钱。
  • top-k 不是 100 的整数倍 —— Cohere 会把每次查询向上取整到整次检索，所以成本是阶梯式上涨，而不是平滑变化。
  • Cohere Fast 对比 Voyage rerank-3 —— 只有当 query 加段落占满最后一块的 80% 以上时，Fast 才更便宜。-lite 档在任何负载下都比两者便宜。

2026 年 10 月更正：此前本页说 Cohere 按 500 token 拆分计费是误传，并称按次计费与段落长度无关。Cohere 自己的价格 FAQ 写的正相反：文档（连同 query）超过 500 token 就会被拆分，每一块都计入每次检索的 100 篇文档。计算器现已按此建模，旧版里 Cohere 在长段落上的优势也随之消失。

那自托管呢？

自托管没有按调用计的价格，所以它不适合放进上面的表里 —— 你是用 GPU 账单加运维成本换掉了用量账单。只有放到你自己的量级上比较才有意义：把每月 GPU 成本除以上面的查询次数，再和表中的每次查询成本对比。每月几十万次查询以下，API 通常比一块专属 GPU 便宜；远高于这个量级后，自托管 Qwen3-Reranker 或 bge-reranker-v2-m3 才开始划算。服务端怎么搭见我们的自托管指南。

另外，模型小并不等于差 —— Jina Reranker v3.5 以 0.6B 的体量，在 Jina 自己的测试里拿到 63.20 的 BEIR nDCG@10，与 4B 模型持平，所以最省资源的那个，也可能是最准的之一。

假设与来源

  • Cohere Rerank 4 —— 每次检索 $0.0025（Pro）和 $0.002（Fast）。一次检索 = 一个 query 加最多 100 篇文档；按 Cohere 价格 FAQ，文档连同 query 超过 500 token 就会被拆分，每一块算一篇文档。价格取自 cohere.com/pricing（每千次检索 $2.50 和 $2）。
  • Voyage rerank-3 —— 每百万 token $0.05，rerank-3-lite 为 $0.02。计费 token = query 按每篇文档各算一次，再加上你发送的全部文档 token —— 所以 50 个候选意味着 query 被计费 50 次。旧版 rerank-2.5 及其 -lite 的单价相同。这里没有计入免费 token 和 Batch API 折扣 —— 哪些模型适用，见 Voyage 专页。
  • token 数为近似值 —— 各家分词方式不同，本页是用你填的平均值相乘，而非对真实文本做分词。
  • 价格于 2026 年 10 月 1 日核对，本站的来源检查每天都会对照 Cohere 和 Voyage 复核一次。做预算前请再确认。
